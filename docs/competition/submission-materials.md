>

## 2. 开题报告 Part 1｜命题前置分析与洞察

### 当前提交文本

我查阅了赛事公开信息、舜宇光学公开资料及精密光学制造相关案例后认为，本命题的核心是把调机过程中的设备状态、工艺参数、质量结果和历史经验连接起来，帮助现场人员更快定位异常、减少无效试错，并让成功经验可复用。考虑到比赛阶段难以获得企业真实产线数据，我计划聚焦精密光学装调中的单一工站，采用公开资料、规则约束的模拟数据和离线回放，完成异常识别、根因排序、安全范围内的参数建议、人工确认及复盘沉淀，形成可运行、可演示、可量化评估的调机决策支持原型。

## 3. 开题报告 Part 2｜整体解决方案设计

**报名要求：** 建议 300—600 字；需清晰阐述方案思路，保证架构完整性、创新性和预期业务价值。建议覆盖整体概述、架构与模块、核心创新、量化价值、可行性与推广性。

### 当前提交文本

我计划将「智造调机助手」建设为面向精密光学装调单一工站的 AI 调机决策支持原型，服务调机人员、工艺工程师和质量人员。系统设置数据采集与归集模块，自动汇总设备状态、工艺参数、质量指标和报警日志；比赛阶段采用 CSV 批量导入和离线回放模拟采集过程，并预留 MES、QMS 及设备日志接口。当出现首件不良或短时良率波动时，系统完成异常识别、Top-3 根因排序和相似案例检索，再生成安全范围内的参数调整候选。每项候选均须通过合法区间、调整步长和参数联动规则校验；证据不足或存在冲突时，只给出排查建议，不输出执行参数。工程人员确认后，系统在离线环境中回放调整结果，对比关键质量指标并生成复盘报告。

系统采用三层架构：数据与知识层承载 CSV、公开数据、规则化模拟数据、SOP、FMEA 和历史案例，并预留 MES、QMS 及设备日志接口；分析与决策层负责异常检测、根因排序、案例匹配和安全校验；应用与闭环层负责任务创建、证据展示、人工审批、结果对比和知识审核。大模型仅用于信息整合、依据解释和报告生成，不直接控制设备。

每次任务结束后，系统将“异常现象—数据证据—根因—调整动作—处理结果—适用条件”整理为待审核案例，审核通过后进入知识库，并用于后续诊断和案例匹配，实现“调一次、学一次”。原型阶段重点验证 Top-3 根因命中率、案例检索命中率、参数建议合法率、越界拦截率和首轮排障时间，并观察调整后质量指标的模拟变化。系统通过减少异常定位时间、无效试调和重复错误，为现场良率改善提供决策支持，但不直接控制设备或替代工程人员。

### 当前比赛版本补充：双层 AI

当前实现由两层 AI 组成：底层 `TuneWise Deterministic AI Core` 负责 Detect、Diagnose、Recommend、Validate、Replay 与受控 Execute；上层已发布的 `Feishu Aily Generative AI Collaboration Layer` 通过 Workflow Application、Knowledge Space Retrieval / RAG 与 LLM 负责 Retrieve、Explain、Trace 与 Answer。TuneWise 负责产生可验证的工业决策证据，飞书 Aily 负责把这些证据和工程知识组织为自然语言解释。

Aily V1 只连接 `Versioned Project Knowledge + Fixed Demo Evidence`，没有 Evidence Bridge、MCP、HTTP Request、Custom Connector 或 Runtime API。它不实时读取 TuneWise 运行状态，不生成生产参数，不修改 `ConfirmedPlan`，不触发 Replay，也不执行 OPC-UA write。

## 4. 不可突破的事实与实现边界

- 比赛阶段不假定能够获得舜宇真实产线数据。
- CSV 批量导入和离线回放用于模拟自动采集过程。
- 不声称已经接入 MES、QMS 或设备系统，只预留接口。
- 不声称 AI 能够直接修改真实设备参数。
- 不声称已经提升舜宇真实现场良率。
- 参数建议必须可追溯、可校验、可拒绝，并保留人工确认。
