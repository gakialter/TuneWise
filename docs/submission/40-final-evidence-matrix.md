## 使用结论

1. 正文只采用 `HIGH` 主张作为“已完成/已验证”事实；`MEDIUM` 主张统一写成场景分析、方法级价值、预期价值或待验证路线。
2. 固定 Demo 与 Process-aware Demo 必须分开展示；所有 Demo 数字同时携带 synthetic、relative ranking score 或 deterministic simulation 语义中的相应边界。
3. “真实运行界面”只证明当前软件或 Aily UI 的实际表面证据；不得升级为真实产线、真实设备、真实数据、准确率或生产效果验证。
4. 图 7 的截图只支持固定 Demo Hero QA，明确不是 Process-aware Q5；Q5 PASS 只能引用人工验收记录。
5. 队名与成员身份由参赛者本人明确提供；手机号与邮箱只允许进入最终官方表字段材料，不得扩散到公开正文或截图。
6. LOROS 只支持公开真实光学数据的语义边界审查；`NO-GO` 不得写成真实 AA 验证 `PASS`。
7. 旧 `Cobalt_v2.pdf` 不作为当前事实源；当前工程事实由 README、submission/competition/validation、版本化资产与实现共同约束。
