# TuneWise 项目概览

## TuneWise 是什么

TuneWise 是面向精密光学主动对准（Active Alignment，AA）工站的 Human-in-the-loop AI 调机决策支持原型。当前本地离线原型覆盖一个代表性异常：中心调制传递函数（Modulation Transfer Function，MTF）合格或临界合格，但四角 MTF 出现不对称下降。

TuneWise 的目标不是让 AI 自动控制设备，而是把一次异常处理组织成可解释、可拒绝、可追溯的工程流程。AI 负责分析异常、进行根因排序、检索适用案例并形成参数候选与证据；工程师负责审核并选择/确认。之后才进入 Simulation Validation (Replay) / 执行前仿真验证，以及显式启用、受控门禁下的 sandbox 执行原型。

## 当前原型解决的问题

- 把分散的测量、参数、规则与历史案例组织成统一证据链。
- 用固定模型和显式规则辅助工程师排查异常，而不是只依赖个人经验。
- 在参数候选进入回放或本地模拟设备执行前，执行统一安全校验与人工确认。
- 用版本和 SHA-256 hash 绑定输入、模型、规则、候选、确认方案、回放结果与执行凭证。

## 工程师工作流

1. 导入版本化 AA 演示 CSV，并校验原始文件 hash 与规范化观测 hash。
2. 用 SPC 规则把批次路由为 `TARGET_ANOMALY`、`NORMAL`、`NON_TARGET_GLOBAL_DEGRADATION` 或 `INSUFFICIENT_DATA`。
3. 对目标异常运行 Top-3 根因排序，并查看显式规则、关键观测和 logit 贡献。
4. 可选地引入 Process Context，例如初始评估/调整后评估阶段、前一步动作、前一步结果与迭代信息，以决定哪些兼容的 `APPROVED` 案例有资格作为证据。
5. 对有资格的案例沿用现有 50-D 结构化距离排序，再依据方向规则和规则/案例幅值证据生成候选，由 `ParameterSafetyValidator` 校验。
6. AA 工艺工程师人工确认候选，形成不可变 `ConfirmedPlan`。
7. 执行 Simulation Validation：先完成 baseline reproduction，再进行固定场景、固定扰动和固定 seed 的配对模拟回放。
8. 仅在显式本地 `OPCUA_SANDBOX` 演示模式、回放 `SUCCESS`、再次人工确认并通过全部门禁后，才可向本机模拟设备执行单参数变化。

## 与传统调机的区别

传统调机容易把判断、试调和经验保存在个人或分散载体中。TuneWise 把每个判断连接到可查询的测量、特征、规则、案例、版本和 hash，并允许证据不足时拒绝继续。它仍然保留人工确认，不声称自动完成设备调优，也不声称候选是最优参数。

## 当前已经完成

- 单一 AA 工站固定演示数据与完整性校验。
- SPC 异常路由、50 个固定工程特征、五类根因的 Top-3 排序。
- `APPROVED`-only 结构化 KNN 案例检索。
- Process-aware 案例资格与解释：这是当前真实运行的软件功能；在当前异常和根因证据之外，可选的过程阶段、前一步动作/结果和迭代上下文可以改变哪些历史案例有资格支持 `CASE_GUIDED`。Process Context 不进入现有 Logistic Regression classifier，也不直接计算参数值；功能可运行不表示 process context 来自真实生产。
- 方向证据、三类候选策略和统一参数安全验证。
- 不可变 `ConfirmedPlan`、过期/篡改保护、baseline reproduction 和确定性配对回放。
- 显式启用的本地 OPC-UA sandbox 单参数受控执行、回读、幂等记录、不可确定结果与只读 reconciliation 语义。
- 真实设备 shadow 数据的只读契约、映射和分析框架；当前仓库只有 synthetic contract fixture。

## 当前尚未完成

- 未接入真实光学产线、真实 PLC、MES、QMS 或真实设备。
- 未使用或验证舜宇真实生产数据；当前固定 Demo 是规则约束的合成数据。
- 未证明真实产线良率提升、调机时间下降、生产收益或真实因果效果。
- 未实现真实设备的生产安全认证、多参数原子执行、自动回滚或真实设备安全联锁。
- 当前声明式 Shadow review 不等于外部验证或专家 ground truth。
- `ProcessContext` 与 `CaseProcessProfile` 当前使用 synthetic fixtures；过程状态名称是 TuneWise 抽象，不是行业标准状态或舜宇内部 SOP，兼容性规则尚未经过真实企业过程数据验证。
- Process-aware Demo 不证明真实 AA 推荐准确率、真实良率提升、production tuning effectiveness、causal effectiveness、sequential optimization 或真实设备效果。

## 飞书 Aily 的角色

飞书 Aily 是 `Generative AI Collaboration / Engineering Explanation Layer`，即生成式 AI 协作与工程解释层。V1 只检索本知识库并解释项目、规则、固定 Demo 证据和事实边界。

Aily 不进入 TuneWise 安全关键控制链，不生成参数，不创建或修改 `ConfirmedPlan`，不触发 Replay、`SimulatorGateway`、DeviceExecution 或 OPC-UA 写入，也不修改 TuneWise Deterministic AI Core 的决策。
