# 04 — TW-04 输出 Top-3 根因、证据充足度与结构化解释

**What to build:** 提供可重复的模型资产生成命令，并让目标异常 Batch 得到稳定 Top-3 根因、类别门控、证据充足度和结构化解释。工程师能够核查得分、显式规则、关键观测、logit 贡献、冲突和可调性。

**Blocked by:** 03 — TW-03 检测四角 MTF 不对称并路由保护分支。

**Status:** ready-for-agent

- HG：HG-02、HG-07、HG-08、HG-09、HG-10、HG-15、HG-16。

## Acceptance criteria

- [ ] 提供可重复执行的命令，从允许训练分区生成固定 StandardScaler、multinomial logistic regression 模型和固定顺序特征定义。
- [ ] 生成结果将模型、预处理器、特征顺序、训练资产清单、随机种子、版本和内容哈希绑定；相同输入重复构建得到相同业务制品与哈希。
- [ ] 本票可使用开发规模训练资产完成真实流水线；不得伪造模型输出，最终冻结资产规模与质量门槛由 TW-11 验收。
- [ ] 推理只使用允许的批次级可观测特征，不含 FaultTruth、隐藏类型/系数、batch_id、分区识别字段、回放结果或案例审核根因。
- [ ] `Z_DEFOCUS_CONDITIONAL` 按冻结条件门控，移除后对其他类别输出重新归一化；硬规则不得暗中加分改变模型排序。
- [ ] Top-3 稳定排序，每项展示归一化得分、显式规则、关键观测、3–5 个主要正向 logit 贡献、冲突和可调性。
- [ ] 所有解释严格使用“该特征对当前类别 logit 的贡献”，不得称为概率贡献、因果贡献、SHAP 或真实故障概率。
- [ ] EvidenceSufficiencyEvaluator 产生版本绑定的 `SUFFICIENT_EVIDENCE` 或 `INSUFFICIENT_EVIDENCE`；证据不足时仍显示排查顺序但任务不能进入 `PLAN_READY`。
- [ ] 通过依赖测试和调用计数证明诊断与证据判断期间 SimulatorGateway、大模型和网络调用均为零。

## 本票不包含

最终冻结规模训练/盲测验收、案例索引、参数候选、人工确认和回放。

## 独立验证

重复构建开发规模模型资产并比较版本与哈希；用可调、不可调、Z 门控和证据冲突夹具核对 Top-3、解释、状态推进、模型输入白名单及模拟器零调用。

## TDD 与边界

- 使用 `/tdd`：是。
