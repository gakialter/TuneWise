# 11 — TW-11 运行隔离离线评估、基线对比与模块级硬门槛审计

**What to build:** 为评审者提供一个隔离、可重复的离线评估入口，使用冻结资产生成异常检测、根因、案例检索、安全、确定性、资产隔离及模块级 HG 证据，并与四种冻结基线比较。未达算法门槛时如实失败和报告，不降低盲测难度。

**Blocked by:** 09 — TW-09 安全处理回放拒绝、异常恢复、并发与幂等。

**Status:** ready-for-agent

## 规格追踪

- 规格章节：8.3–8.5、23、24、25、26.8、27。
- AC：AC-D4-02、AC-D4-03、AC-D4-05、AC-D5-01、AC-D5-02、AC-D5-05、AC-D6-04..08、AC-D8-01..04。
- HG：产生 HG-01..12、HG-15、HG-16 的算法/模块/隔离证据，并产生与模块表面有关的 HG-09、HG-10、HG-14 证据；实际报告、实际导出、新提交 PENDING_REVIEW 和完整展示层的跨模块放行明确留给 TW-12。

## Acceptance criteria

- [ ] 冻结评估资产满足训练集不少于 200 Batch、验证集不少于 50、盲测集不少于 100、盲测五类各不少于 20、APPROVED 案例不少于 60。
- [ ] 独立检测集覆盖 NORMAL、TARGET_ANOMALY、NON_TARGET_GLOBAL_DEGRADATION、INSUFFICIENT_DATA、单点噪声和临界控制限。
- [ ] Batch 级切分、集合 ID/种子互斥、演示批次隔离、案例来源隔离、集合清单、版本和内容哈希全部验证。
- [ ] 评估命令从冻结资产重新生成或加载模型、预处理器、特征定义和 APPROVED 索引，并核对其来源、版本和哈希绑定。
- [ ] 检测报告包含每类支持数、混淆矩阵、Precision/Recall/F1、错误路由、噪声误触发及规则版本，并执行冻结阈值。
- [ ] 根因报告按 Batch 计算 Top-1、Top-3、macro-F1、混淆矩阵，区分模型独立与端到端业务评估，并保留 Z 类结果。
- [ ] 检索报告包含各类别查询数、有/无相关案例数、Recall@3/5、NO_RELEVANT_CASE_AVAILABLE 和失败明细。
- [ ] 固定四种基线均在隔离评估中运行；参数风险基线不生成可确认计划且不调用设备或模拟器。
- [ ] 生成非法参数、证据不足、不可调故障、PENDING 污染、STALE、前端篡改、回放幂等和基线重现的模块级硬门槛证据。
- [ ] 使用固定演示输入连续运行 10 次，比较检测、Top-3/得分/贡献、案例顺序、候选/哈希、确认哈希和回放指标/状态/哈希。
- [ ] 通过可测试调用计数证明检测、诊断、检索、方向证据、候选生成和安全校验期间 SimulatorGateway 调用均为零。
- [ ] 运行时包/依赖、数据库、接口、日志和模块结果的 FaultTruth/隐藏信息扫描结果为零；隔离标签目录本身不被误判，但须证明运行时未访问。
- [ ] 未达算法质量门槛时不得改盲测标签、删难例、重生成简单集合或加入演示批次；报告失败与限制并以非通过状态结束。
- [ ] 本票不得声称已经完成实际报告、实际导出、新提交 PENDING_REVIEW 路径或最终比赛 UI 的全部端到端 HG 放行。

## 本票不包含

完整闭环展示层、实际新提交案例跨模块污染验证、最终报告/导出表面放行、Windows 打包和发布验收。

## 独立验证

从冻结 Manifest 运行评估入口，核对退出状态、版本哈希、指标、基线、拒绝分布、10 次确定性、调用计数、泄漏扫描和模块级 HG 证据账本；故意注入一个门槛失败，确认评估不会伪造通过。

## TDD 与边界

- 使用 `/tdd`：是，评估口径、泄漏扫描、调用计数和门槛判定必须可重复验证。
- SimulatorGateway：仅可由回放模块测试替身或隔离模拟评估使用；诊断/检索/方向/候选/安全以及参数风险基线调用数为零。
- FaultTruth：仅隔离训练和评估流程可读，业务运行时不可读。
- 隐藏场景：仅隔离模拟资产和回放测试使用，业务响应不可见。
- APPROVED 案例：验证只来自允许训练分区；PENDING、测试、验证、盲测和演示来源污染数为零。
